## 背景与现状（2026-10-06 核实）

- **成功案例：jasmine-lottery 抽奖页素材**（2026-10-05，该仓 `assets/papercut-garden/`、`assets/prize-placeholder/`、`assets/activity-qr/` 与 ADR `docs/decisions/2026-10-05-h5-papercut-garden.md`）。Claude Code 用一个 grsai 出图脚本直接产出了页面在用的定稿素材，四张 AI 原图全部用 `gpt-image-2-vip`：

  | 素材 | 尺寸 | 最后怎么用 | 透明底怎么解决 |
  |---|---|---|---|
  | 抽奖页后景（纸雕灯箱夜空） | 2160×3840 | 整张铺底，缩到 1500×2667 | 不需要透明 |
  | 角落枝条剪影 | 2160×3840 | 抠出形状、描成矢量、可点亮 | 提示词要求纯黑剪影 + 纯白底 → 灰度 128 二值化 → vtracer 描矢量（矢量天生透明） |
  | 三盏南瓜灯剪影 | 2048×2048 | 同上，刻痕要能透光 | 同上 |
  | 五枚奖品占位徽章 | 2880×2880 | 一张拼五枚，切成圆形小图 | 在页面夜色同色的纯色底（`#1B1D3C`）上出，按与底色的差异找块、裁正方形，页面再裁圆 |

- 那次**试过、被否**的路线（ADR 原文）：让 AI 直接出透明底——`background=transparent` 不生效，退成白底后白花瓣抠出来发虚；用抠图模型（BiRefNet_HR-matting）抠用户原画——含苞版 32%、盛开版 43% 的像素抠成半透明，天空残留成灰网。活动二维码另调研了 6 个方向，选了纯代码画的那版：AI 画码「每次都可能画错格子，要逐张验」（该仓 `assets/activity-qr/README.md`）——要求精确的东西不交给 AI。
- 那次**做对的事**：
  1. 出图前先定「这张图最后怎么用」，再倒推出图方式——透明底是靠这一步绕开的，不是靠接口参数；
  2. 尺寸按落地需要倒推（三倍屏全屏背景要到 4K 档）→ 只有 1~4K 档模型能出，所以用 vip；
  3. 提示词按落地场景写：顶部 15% 留给标题、中间 60% 宽 × 20%~72% 高不放物体（留给盒子）、色值写成页面的 hex、剪影类写死「Pure black and pure white only: no gray, no shading…」、拼图类写死「两行、间距均匀、互不接触、纯色平底」、末尾列「No text, no frame…」；
  4. 提示词原样存档（`prompts/*.txt`）、原图与来源入库（README 来源表写明模型、日期、尺寸、提示词文件、后处理）；出图脚本另写一份同名 `.json` 记参数；
  5. 出图后先叠到页面底色上预览（`_on_night.jpg`），再挑；
  6. 方向没定时先做对比小样给用户挑（AI 版 vs 纯矢量版；徽章第一版被否「像是一个邪恶的女巫」，换第二版）。
- draw 技能现状（#3 合并后的主干，2026-10-06 核对代码）：能出图、能垫本地图和遮罩、能体检透明、有模型目录与尺寸检查；但**不会按需求选模型**（SKILL.md 只写「默认 `gpt-image-2`，可用 `IMAGE_MODEL` 覆盖或 `--model` 单次指定」）；**出图前不判用途**——透明底只有一节「透明素材路线（重要）」，用户提到透明才会看；SKILL.md「流程要点」只有「跑脚本 → 展示图 → 转达错误」三步；`draw.py` 出图后**不留任何参数记录**。
- 透明底的现实（升级 spec「接口契约补充」）：官方只称 vip / flare / sunburst 支持 `background=transparent`；vip 实测不生效，另两个 2026-10-06 处于维护——眼下没有稳定出真透明的路线。

## 目标

把 jasmine-lottery 那次的做法沉淀成技能的默认工作方式：

1. **出图前必判用途**：agent 先把这张图归到四类之一，按类选出图路线；透明底问题在这一步定。
2. **agent 自动选模型**：按「用途 → 尺寸 → 阶段」挑模型，回复里说明理由；用户点名优先。
3. **后处理有思路可循**：拿到图后每类给几句常见下一步，**仅供参考、不强制**，agent 自行判断。
4. **提示词按落地场景写**：给出写法要点与案例。
5. **出图可追溯**：每张图旁边自动留一份参数记录。

## 机制清单

| 机制 | 解决什么 | 没有它会怎样 |
|---|---|---|
| 1. 出图前判用途（必经一步）：四类——整图 / 抠形状 / 拼图 / 透明位图，每类一条出图路线；判定结果在回复里亮给用户；拿不准就问用户 | 透明底需求在出图前就定好路线 | 出完才发现要抠图，而且抠不干净；或者反复试透明参数、反复拿到白底 |
| 2. agent 自动选模型：用户点名 → 透明位图 → 超出 1K → 探索期 → 默认，按顺序判；回复里一句话说明理由 | 要高清、要试透明时，用户不用自己懂模型 | 不点名就永远只出 1K；要透明时选到不支持的模型 |
| 3. 后处理思路（只写成文字指导、不强制）：按四类各写几句常见下一步，开头明写「仅供参考，agent 自行判断，不要照搬」 | 别的 agent 拿到图知道往哪走 | 拿到一张白底图不知道怎么办；或者把某个项目的特例当成规矩照搬 |
| 4. 提示词按落地场景写（文字指导）：用途、布局留位、色值、用途约束、写明不要什么，附 jasmine 四条提示词的要点 | 出的图能直接放进去用 | 图好看但放不进页面，比如中间没留位置、多了文字和边框 |
| 5. 出图记录：每张图旁边自动写一份同名 `.json`，记录提示词、模型、尺寸、参数、用途、任务 id、时间；用途由新参数 `--use` 传入，**只记录、不改变任何出图行为** | 以后能复现、能追溯「这张图怎么来的」 | 过几天就说不清用的什么提示词和模型；AI 每次出图都不一样，没法重出同一路子 |

## 设计

### 机制 1：出图前判用途（SKILL.md，必经一步）

agent 调 `draw.py` 之前，先回答「这张图最后放在哪、怎么叠」，归到下面四类之一：

| 类 | `--use` 值 | 什么时候是这类 | 出图路线 |
|---|---|---|---|
| 整图 | `full` | 整张铺满一块区域，四边不需要露出底下的东西：背景、海报、插画、封面 | 正常出图，不要透明 |
| 抠形状 | `cutout` | 单个元素要从背景里拿出来、叠在别的东西上：图标、剪影、装饰、贴纸 | **单色能接受**（剪影、要描矢量、要能「点亮」）→ 提示词写死纯黑剪影 + 纯白底、无灰阶；**要保留颜色** → 纯色平底出图，底色与主体反差大（纯白或纯绿），提示词写「纯色背景、无阴影、无渐变」 |
| 拼图 | `sheet` | 多个同风格的小元素：一组图标、徽章、占位图 | 一张图拼多枚，写明个数与排布、间距均匀、互不接触；底色**优先用落地页面的底色**——切下来不用抠就能直接用 |
| 透明位图 | `alpha` | 主体本身带半透明（光晕、烟雾、玻璃），抠形状替代不了 | 先跟用户说明「眼下没有稳定的真透明出图」；只在官方称支持透明的模型上试 `--background transparent`，出图必跑 `--inspect`；判「不是真透明」或「存疑」→ 退回「抠形状」的纯色底路线 |

- 判法顺口诀：**能整张用就不抠；能用落地底色就不透明；能接受单色就走剪影；真有半透明才走透明位图**。
- 判定结果在回复里写一行：「用途：抠形状（单色剪影，之后描矢量）；模型：…（理由）」。
- 拿不准（请求里看不出怎么用）→ 先问用户一句，用四类做选项；不猜。
- 每次调用都带 `--use`，让出图记录里留下这次的判定。

### 机制 2：agent 自动选模型（SKILL.md）

按顺序判，命中即停：

1. **用户点名了模型** → 用点名的；如果和下面的规则冲突（比如点了 1K 模型却要 4K 图），用一句话提醒限制，仍按用户的来。
2. **用途 = 透明位图** → 候选只有官方称支持透明的三个：`gpt-image-2-vip` / `gpt-image-2.5-flare` / `gpt-image-2.5-sunburst`。但 vip 的 transparent **实测不生效**、另两个 2026-10-06 在维护——**眼下没有真能出透明的**；先按机制 1 说明，再在当下不在维护的候选里试（2026-10-06 只剩 vip，试它是确认现状、**预期不成**），flare / sunburst 恢复后优先试它们。出图必跑 `--inspect`，不成退回纯色底。
3. **需要的尺寸超出 1K** → 用 1~4K 档模型，优先 vip。判法：目标像素 = 落地显示尺寸 × 设备像素比（手机按 3 倍），任一边超过所选比例的 1K 预设 → 上 2K / 4K 档。例：手机全屏竖版背景约 1125×2436 → 超出 1K → 选 `1152x2048` 或 `2160x3840`。
4. **探索期**（方向还没定、要先出几版给用户挑）→ 用 `gpt-image-2` 出 1K 小样，一般 2~3 张；方向定了再按 2、3 条出定稿。⚠️ 换模型后风格可能变：想保住小样的感觉，可以把选中的小样当 `--ref` 垫图再出定稿（思路，效果不保证）。
5. **其余** → `gpt-image-2`（脚本默认，1K、最便宜）。

- 回复里一句话说明理由，例：「用 vip：要 2160×3840 的全屏背景，1K 模型出不了」。
- 价格只做定性比较（gpt-image-2 最便宜、1~4K 档更贵），具体数字看官方模型页——与升级 spec「价格不进 spec / 代码」的口径一致。
- 尺寸怎么写见 `--list-models`（升级 spec 修订二：1K 档 13 档预设，可写比例或像素值；1~4K 档 43 档预设，只收像素值）。

### 机制 3：后处理思路（`references/after-draw.md`，不强制）

文件开头固定一句：**「以下是 jasmine-lottery 2026-10-05 实战里走通的做法，仅供参考。按你手上项目的实际情况判断，不要照搬；没把握就先问用户。」** 正文按四类写，每类 3~5 行：

- **整图**：按落地尺寸缩放（目标像素 = 显示尺寸 × 设备像素比），转 webp / jpg 压体积；原图另存一份高质量存档。
- **抠形状 · 单色剪影**：先按灰度阈值（如 128）二值化，去掉灰边和噪点；再描成矢量（如 vtracer、potrace）。矢量天生透明、放多大都清楚，还能分层上色、做「刻痕透光」。
- **抠形状 · 纯色底彩色**：按底色色键抠，或用抠图模型；边缘常有残色、半透明，抠完用 `alpha_check.py --bg <落地底色>` 叠上去看一眼。
- **拼图**：按与底色的差异找连通块 → 每块取外接框裁切；底色就是落地页面底色时，裁完可直接用。
- **透明位图**：出图后看 `--inspect` 结论；判「不是真透明」或「存疑」→ 退回纯色底路线；判「真透明」也要 `--bg` 叠到落地底色上看边缘有没有灰边。
- **通用**：提示词、原图、出图记录一起存档；AI 每次出图都不一样，换素材要重出、重挑。

### 机制 4：提示词按落地场景写（`references/prompting.md`）

写法要点（每条一句 + jasmine 例子）：

1. **写清用途和落地位置**：例「used as the background plate of a mobile Halloween night page」。
2. **布局留位**：用百分比说清哪里不放东西，例「Keep the top 15% plain dark sky (a title will sit there)」「no objects in the middle 60% of the width between 20% and 72% of the height」。
3. **色值对齐落地页面**：直接写 hex，例「deep midnight indigo (#11132A …)」。
4. **用途约束写死**：剪影类「Pure black and pure white only: no gray, no shading, no texture」；拼图类「arranged in two rows … generous even spacing … none touch each other」；纯色底类「plain flat … background」。
5. **写明不要什么**：AI 爱加文字、边框、多余元素，例「No text, no frame, no border」。
6. **风格要否掉时，用用户原话改方向**：例徽章第一版被说「像是一个邪恶的女巫」，第二版提示词写「Cozy and kind … Not spooky, not dark … no witchy or magical mood」。

文件末尾链接 jasmine-lottery 的四份提示词原文位置（`assets/papercut-garden/prompts/` 3 份 + `assets/prize-placeholder/prompt.txt`；只给路径，不复制全文）。

### 机制 5：出图记录（draw.py）

- 新参数 `--use {full,cutout,sheet,alpha}`：选填，**只写进记录**，不影响请求体、模型、体检等任何行为。
- 每张图下载完成后，在图片旁写同名记录：`draw-<任务id>-<序号>.json`（图片文件名去掉扩展名 + `.json`）。
- 记录字段：

  ```json
  {
    "prompt": "…",
    "model": "gpt-image-2-vip",
    "aspect": "2160x3840",
    "quality": "medium",
    "background": null,
    "refs": ["https://…/a.png", "/abs/path/local.png"],
    "mask": null,
    "use": "full",
    "base": "https://grsai.dakka.com.cn",
    "task_id": "…",
    "index": 1,
    "image_url": "https://…",
    "created_at": "2026-10-06T14:03:21+08:00",
    "seconds": 63
  }
  ```

- 本地参考图 / 遮罩只记**绝对路径**，绝不写 base64；**绝不写 key**。
- `--url-only`：没有本地文件，不写记录。
- 记录写失败（权限、磁盘）→ stderr 警告一行，出图照常算成功、退出码 0。
- stdout 契约不变（只打图片本地路径）；记录路径不进 stdout。

## 错误处理（增补；其余沿用升级 spec）

| 情况 | 行为 |
|---|---|
| `--use` 值不在四个里 | 报错（列出四个可选值），退出码 2 |
| 记录写失败 | stderr 警告，出图照常，退出码 0 |

## 测试

- `--use`：四个值都能写进记录；非法值退出码 2；不传时记录里 `use` 为 `null`。
- 记录：桩掉 `generate` 与下载跑通 `main` → 每张图旁边有同名 `.json`，字段齐全；本地 `--ref` 记成绝对路径，文件内容不含 `base64`；文件内容不含 key 字符串；`--url-only` 不写记录；把输出目录设成只读 → stderr 有警告、退出码 0；stdout 仍只有图片路径。
- `--use` 不改行为：同一组参数带 / 不带 `--use`，请求体逐字段相同。
- 样例走查（人工，按 SKILL.md 走一遍，判定与下表一致即过）：

  | 请求 | 用途 | 模型 |
  |---|---|---|
  | 「给抽奖页做一张手机全屏夜空背景」 | 整图 | 1~4K 档（vip），尺寸 2K / 4K 竖版 |
  | 「三盏南瓜灯，要能单独摆在页面上、刻痕能点亮」 | 抠形状（单色剪影） | 探索期 gpt-image-2；定稿按描边需要的尺寸定 |
  | 「五枚奖品占位图，放在深靛蓝页面上」 | 拼图（底色用页面色） | 一张 2880×2880 → vip |
  | 「一个半透明发光的魔法光球，叠在各种背景上」 | 透明位图（先说明可能不成） | vip，带 `--background transparent` 与 `--inspect` |
  | 「随手画只猫看看」 | 整图 | gpt-image-2 |

## 不做（YAGNI）

- 后处理工具进技能（描矢量、色键抠图、切块）：用户拍板只给思路；那次的三个后处理脚本都是为页面定制的。
- `--use` 改变行为（自动加提示词、自动体检、自动选模型）：判断留给 agent，脚本不做魔法——与升级 spec「`--inspect` 显式开关，不做魔法」一致。
- 脚本层自动选模型（如 `--model auto`）：用户拍板「agent 按需挑」，规则写在 SKILL.md。
- 关闭记录的开关：先不做，嫌多再加。
- 记录里存体检结论：体检报告已走 stderr，两者解耦。
- 价格数字进 SKILL.md / references：价格变动快，只做定性比较、指向官方页。

## 自定细节

1. 四类的参数值：`full` / `cutout` / `sheet` / `alpha`；中文名：整图 / 抠形状 / 拼图 / 透明位图。
2. `--use` 选填（保持老用法 `draw.py "一只猫"` 能跑）；「必经」靠 SKILL.md 约束 agent，不靠脚本强制。
3. 抠形状类再分两条路线（单色剪影 / 纯色底彩色），不拆成两个 `--use` 值——差别只在提示词，记录里看提示词即可。
4. 纯色底的颜色沿用升级 spec 自定细节 27 的口径：纯白或纯绿；拼图类例外，优先用落地页面底色。
5. 选模型规则里「1K 以上」的判法：目标像素 = 显示尺寸 × 设备像素比（手机按 3）；任一边超过所选比例的 1K 预设 → 上 2K / 4K。
6. 高清「优先 vip」：依据是 2026-10-06 官方模型页上 1~4K 档只有 vip 不在维护。透明位图不套这条——vip 出透明的能力实测不生效，选它只是因为另两个在维护、没有别的候选（见机制 2 规则 2）。
7. 探索期小样一般 2~3 张，用 `gpt-image-2`。
8. 回复里亮判定的格式：一行「用途：X（路线）；模型：Y（理由）」。
9. 记录文件名 = 图片文件名去扩展名 + `.json`，与图片同目录；JSON 用 UTF-8、`ensure_ascii=False`、缩进 2。
10. 记录字段与顺序见「机制 5」；`created_at` 用本地时区 ISO 8601（精确到秒）；`seconds` = 从发起请求到这张图下载完成。
11. 记录里写 `base`（接口域名，不是秘密，便于知道走的哪个节点）；本地路径一律转绝对路径。
12. 两份指导文件放技能目录下的 `references/`（`after-draw.md`、`prompting.md`）：SKILL.md 保持精简，需要时再读；「仅供参考」的内容与「必经」的内容分开放，不混淆。
13. jasmine 提示词只给路径、不复制全文：那四份提示词是那个项目的资产，复制过来就成了会变旧的副本。
