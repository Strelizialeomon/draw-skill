## 背景与现状（2026-10-06 核实）

- draw 技能（`~/code/draw-skill`）当前只认环境变量；而 shell 配置与 Claude 设置里都没有这些变量，代码也不读仓库内的 `.env`。**结论：现在装好即跑会退出码 2，必须先手动 export 才可用。**
- 2026-10-05 在 jasmine-lottery 出素材时写的 `assets/papercut-garden/scripts/gen_image.py` 沉淀了三条经验：
  1. 接口接受**本地图转 base64 data URL** 当参考图（该脚本以本地文件路径为入参，实战出图走通过）；
  2. key 可以放 `~/.config/grsai/key` 文件（该文件现已存在）；
  3. AI 出图的「透明底」经常是假的（白底 / 棋盘格画进图里 / 干脆没通道），出图后需要**透明通道体检**才能下结论。
- SKILL.md 有两处旧描述（frontmatter 描述、正文首段写成「轮询等待」），README 首段也写成「提交 → 轮询 → 取图」（`README.md:3`）；实际实现是 SSE 流式。
- grsai **没有模型列表 API**（2026-10-06 实测）：境内、境外节点的 `/v1/models`、`/v1/draw/models` 等候选端点全部 404；官方文档只定义 `/v1/draw/completions` 与 `/v1/draw/result` 两个接口。官方模型页 `grsai.com/zh/dashboard/models` 免登录、服务端直出——本次已从其页面数据抓出在架**图片模型 15 个**（GPT 系 5 个 + nano-banana 系 10 个）。
- （修订二）gen_image.py 的透明体检「四角 + 下半中间留白区」探针是为剪纸花园那批「主体偏上、下方留白」的素材定制的，**通用场景会误判**：用 Pillow 合成两张真透明图实测——居中圆形贴纸（留白区 alpha 均值 176）、贴底主体（203）——都被判「不是真透明」。另外它依赖 numpy，不是只要 Pillow。
- （修订二）官方文档的参数细节由前端脚本渲染，网页正文抓不到；本次从 GPT Image 文档页的前端脚本与官方「新文档」（分辨率规则页）补抓到：尺寸规则、`background` 支持名单、`mask` 参数、失败原因枚举、上传限制、结果链接有效期（详见「接口契约补充」）。

## 目标

让 draw 技能「装好即用、垫图不受公网限制、出图后能验透明、模型选型不写死」：

1. 不配任何环境变量也能跑（key 走文件、域名走默认）。
2. `--ref` 直接收本地图片路径（自动转 data URL）。
3. 新增透明体检工具（判法：看边框一圈，并说清「为什么不是真透明」）；`--inspect` 可在出图后顺手跑。
4. `--quality` / `--background` 透传。
5. 顺手修 SKILL.md 与 README 的「轮询」旧描述（SKILL.md 两处 + README 首段一处）。
6. 模型不写死：内置「预制模型目录」（GPT 系 5 个），`--list-models` 随时可查；`--model` 保持自由传。
7. （修订二）出图前挡掉明显错参：尺寸不合模型规则、垫图格式不对——尺寸只警告不拦，格式不对直接报错。
8. （修订二）失败给中文原因；官方建议重试的「其它错误」自动重试 1 次（失败退积分）。
9. （修订二）`--mask` 收本地遮罩，支持局部重绘。
10. （修订二）透明素材给出一条可靠的默认路线（文档指引，不承诺 `background=transparent` 的效果）。

|---|---|---|
| 本地垫图直传：`--ref` 收本地路径，自动转 base64 `data:` URL | 手里有垫图、但没有公网 URL 也能垫图 | 垫图只能先传到图床换 URL |
| 配置回退链：key 依次找 `IMAGE_API_KEY` → `GRSAI_KEY` → `~/.config/grsai/key` 文件；域名缺省 `https://grsai.dakka.com.cn` | 新机器 / 新会话开箱即用 | 维持现状：每次手 export，忘了就退出码 2 |
| 透明体检：新增 `alpha_check.py` 工具；`draw.py --inspect` 生成后顺手跑。（修订二）判法 = 边框一圈的透明占比 + 原因分类（没通道 / 边框不透明 / 疑似棋盘格 / 白底） | 判定成图是不是真透明（假透明肉眼难辨），并说清假在哪 | 拿 PS 逐个开来看；旧判法会把居中、贴底的真透明图判成假的 |
| 参数透传：`--quality` / `--background` | 调清晰度、指定底色不用改脚本 | 要用这些参数就得改代码 |
| 模型目录：内置预制模型清单（GPT 系 5 个，快照 2026-10-06）+ `--list-models` 打印。（修订二）只存能力（清晰度档 / 质量档 / 透明支持 / 尺寸规则 + 预设尺寸表），不存价格与状态 | 模型选型可见、不写死；新模型仍可直接 `--model` 传 | 模型名、合法尺寸只能靠记忆或临时翻官方网页 |
| （修订二）尺寸软检查：按目录里的尺寸规则检查 `--aspect`，不合规则在 stderr 警告、照发 | agent 选错尺寸时出图前就有提示 | 错尺寸白跑一次才知道（虽退积分但耗时约 1 分钟） |
| （修订二）失败原因中文化 + 「其它错误」自动重试 1 次 | 失败时用户看得懂原因；偶发错误不用手动重跑 | 只看到 `output_moderation` 之类英文码；偶发错误要人再跑 |
| （修订二）垫图预检：按文件头判格式，只收 png / jpg / webp；超 10MB 或超 6 张只警告 | 格式不对在本地就拦下、报清原因 | 上传 HEIC / GIF 才在接口侧失败，原因含糊 |
| （修订二）本地遮罩 `--mask`：收公网 URL 或本地 PNG（自动转 data URL），透明区 = 要重绘的区域 | 只改图的一块（局部重绘） | 想局部改图只能整张重画 |
| （修订二）透明素材默认路线（仅文档）：默认纯色平底出图 → 本地抠图；`background=transparent` 只在官方支持的模型上试、出图必体检 | agent 有一条走得通的路，不对用户承诺做不到的事 | agent 照 `background=transparent` 反复试、反复拿到白底 |
| （修订二）提示词选填：只跑 `--list-models`（查模型目录 / 预设尺寸表）时可不给提示词 | 查表不用先编一句提示词 | 空跑 `--list-models` 会报错，得随手写句提示词应付 |

## 接口契约补充（2026-10-05 实测 + 2026-10-06 官方文档复核，叠在 2026-06-11 契约之上）

- `urls[]` 元素除公网 URL 外，**接受 base64 data URL**（`data:image/png;base64,...`）。gen_image.py 即按此实现，并以本地文件当参考图出图走通。（修订二）官方文档原文：「参考图片的URL，支持多张图片，支持base64」。⚠️ gen_image.py 走通的是「提交 + 轮询结果」路径，**流式路径带 data URL 尚未实跑**——由真机冒烟补验。**2026-10-06 补验结论：走通**——本地 `--ref` + 本地 `--mask` 走流式接口一次出图成功；遮罩语义（透明区 = 重绘区）实测生效：红底保留、仅遮罩区域被重绘。
- `background: "transparent"` 在 grsai `gpt-image-2-vip` 渠道**不生效**：纯文字出图带它连续 3 次失败（不扣费）；带参考图时被忽略、返回白底 RGB。→ 技能只做透传、不承诺效果；文档必须标注此坑。
  - （修订二）官方文档口径：`background` 只支持 `"transparent"`，且只列了 `gpt-image-2-vip` / `gpt-image-2.5-flare` / `gpt-image-2.5-sunburst` 三个模型。其中 vip 实测不生效，另两个在官方模型页上处于「维护中」（2026-10-06）→ **眼下 grsai 上没有一条稳定出真透明的路线**。
  - （修订二）上游参考（OpenAI，非 grsai）：2026-08-20 起 gpt-image-2 的透明底以「预览」形式开放，要求输出格式为 png / webp；grsai 不暴露输出格式参数——**推测**这是 vip 渠道不生效的原因之一（未验证）。上游已知瑕疵：不透明区 alpha 只到 252~254、主体边缘有灰边。
- `quality`（如 `medium`）实测可用；**支持值随模型不同**，官方文档对照（2026-10-05 抓取）：`gpt-image-2`: auto；`gpt-image-2.5`: auto；`gpt-image-2-vip`: medium；`gpt-image-2.5-flare`: low、medium、high；`gpt-image-2.5-sunburst`: low、medium、high、xhigh、max。
- （修订二）`aspectRatio` 尺寸规则（官方新文档「分辨率」页，旧文档注明「新文档中的像素值通用」）：
  - `gpt-image-2` / `gpt-image-2.5`：只有 1K；收**比例**（如 `16:9`）或 **1K 像素值**。官方 1K 预设 13 档：`1:1=1024x1024`、`16:9=1672x941`、`9:16=941x1672`、`4:3=1443x1090`、`3:4=1090x1443`、`3:2=1536x1024`、`2:3=1024x1536`、`5:4=1408x1120`、`4:5=1120x1408`、`21:9=1920x832`、`9:21=832x1920`、`2:1=1792x896`、`1:2=896x1792`，另有 `auto`。⚠️ 比例写法是新文档（另一个接口）的说法，**在 `/v1/draw/completions` 上未实测**——由真机冒烟补验。**2026-10-06 补验结论：可用**——`--aspect 16:9` 出图 1672×940，与官方 1K 预设 16:9（1672×941）差 1px；比例写法按官方预设换算即可。

- （修订二）`failure_reason` 枚举（官方文档）：`output_moderation` 输出违规 / `input_moderation` 输入违规 / `error` 其它错误；**失败会返还积分**；官方提示「触发 error 时可尝试重新提交任务」。`error` 字段是失败详情。
- （修订二）`mask`（官方文档）：「遮罩图片的URL，支持base64」。语义按上游 OpenAI 约定：PNG、带透明通道，**全透明区 = 要重绘的区域**，尺寸与第一张参考图一致；坑：白底黑形那种常见遮罩没有透明区，接口会当「全部保留」原样返回；社区也报告过遮罩被忽略（遮罩是「提示」不是硬约束）。
- （修订二）上传限制：官方网页上传组件限制最多 6 张、单张 < 10MB、只收 JPG / JPEG / PNG / WEBP；**接口文档没写上限**，只作参考。上游 OpenAI 的编辑接口也只收 png / jpg / webp。
- （修订二）结果图链接**有效期 2 小时**（官方文档 + 帮助中心）：下载模式不受影响；`--url-only` 打出的链接 2 小时后失效。
- **没有模型列表接口**（见「背景」，境内外节点均 404）；在架模型以官方模型页为准，本次抓取快照见「模型目录」。
- SSE 流式契约（`shutProgress:false` + `data:` 帧）不变，继续沿用；不引入 `/v1/draw/result` 轮询。

## 设计

### draw.py（改造，保持零第三方依赖）

调用形态（★ = 本次新增）：

```bash
python3 draw.py ["<提示词>"]           # ★（修订二）改选填：只跑 --list-models 时可不给
  [--model gpt-image-2]
  [--aspect 1024x1024]                  # ★（修订二）按模型目录做软检查
  [--ref <公网URL 或 本地图片路径>]...   # ★ 本地路径自动转 data URL
  [--mask <公网URL 或 本地PNG>]         # ★（修订二）遮罩，本地路径自动转 data URL；须同时给 --ref
  [--quality <档位>]                    # ★ 透传，不传则不发该字段
  [--background <值>]                   # ★ 透传，空串 = 不发该字段
  [--list-models]                       # ★ 打印内置模型目录（离线，不触网）
  [--inspect]                           # ★ 下载后对每张成图跑体检（报告走 stderr）
  [--out <目录>] [--url-only] [--timeout 300]
```

抽出可单测的纯函数（现有 `download` / SSE 解析不动；`generate` 只在失败时多带一个失败原因，见下）：

- `normalize_refs(refs) -> list[str]`：`http://` / `https://` / `data:` 开头原样透传；其余当本地文件读字节 → ~~按扩展名定 mime~~（已被取代（修订二）：改为按文件头判格式，见下条）→ `data:<mime>;base64,...`。文件不存在 → `DrawError`（退出码 2）。
  - （修订二）本地文件**按文件头（magic bytes）判格式**、不看扩展名：PNG `89 50 4E 47 0D 0A 1A 0A`、JPEG `FF D8 FF`、WebP `RIFF????WEBP`；三者以外（GIF、HEIC 等）→ `DrawError`（退出码 2），文案写清「只支持 png / jpg / webp，先转换」。
  - （修订二）软限制只警告不拦（stderr）：单个本地文件 > 10MB；`--ref` 总数 > 6。依据是官网上传组件，接口文档未写上限。
- （修订二）`normalize_mask(mask, has_refs) -> str | None`：没给 → `None`；给了但没有 `--ref` → `DrawError`（退出码 2，「遮罩要配参考图」）；URL / `data:` 原样透传；本地文件必须是 PNG（文件头判定），否则 `DrawError`（退出码 2）；PNG 没有透明通道（IHDR 颜色类型不是 4 / 6、且没有 `tRNS` 块）→ stderr 警告「遮罩没有透明区，接口会当全部保留」、照发。尺寸是否与参考图一致不检查（要解析 JPEG / WebP 尺寸，零依赖下不值），文档写明。
- `resolve_key() -> str`：`IMAGE_API_KEY` 环境变量 → `GRSAI_KEY` 环境变量 → `~/.config/grsai/key` 文件（取 strip）；全无 → 报错退出码 2，文案写清三个来源。
- `resolve_base() -> str`：`IMAGE_API_BASE` 环境变量 → 缺省 `https://grsai.dakka.com.cn`。
- `build_body(...) -> dict`：把现在内联的请求体组装抽成函数；`quality` / `background` 仅在给了值且非空串时带上。（修订二）`mask` 有值时带上。
- （修订二）`check_aspect(model, aspect) -> list[str]`：返回警告文案列表（空 = 没问题），只警告不拦。规则见「模型目录」的尺寸规则：
  - 模型不在目录里 → 不检查；`auto` → 通过。
  - 1K 档模型（`gpt-image-2` / `gpt-image-2.5`）：13 档预设像素值、及其对应的 13 个比例写法 → 通过；其余 → 警告「不在官方 1K 预设里」。
  - 1~4K 档模型（vip / flare / sunburst）：比例写法 → 警告「该模型不收比例，请用像素值」；`宽x高` → 逐条查四条约束，违反哪条报哪条；格式认不出 → 警告。
- （修订二）失败处理：`generate` 遇到 `failed` 事件时，抛出的 `DrawError` 带上 `reason`（即 `failure_reason`）。`main` 按 `reason` 处理：
  - `error` → stderr 打「其它错误，自动重试 1 次（失败已退积分）」后**整次重发 1 次**；再失败 → 退出码 1。
  - `input_moderation` → 「提示词或参考图被判违规，改写后再试」；`output_moderation` → 「生成结果被判违规，换个说法再试」；都不重试，退出码 1，并附原始 `error` 详情。
  - 其它 / 空 → 维持现有文案，不重试。HTTP 非 2xx、网络错误**不**自动重试（不确定是否扣费）。

`--inspect`：下载完成后对每张图调用体检函数，报告打 **stderr**（stdout 只保留「本地路径」契约）；Pillow 未装时 stderr 提示跳过体检、主流程照常、退出码 0；`--url-only` 时无本地文件、不体检。体检函数从 `alpha_check.py` 惰性 import——只有 `--inspect` 才需要 Pillow，主路径仍零依赖。

### 模型目录（draw.py 内置常量）

### alpha_check.py（新增）

```bash
python3 alpha_check.py <图片> [<图片>...] [--bg RRGGBB]
```

- ~~判定逻辑沿用 gen_image.py 实测版：读成 RGBA 后，四角各取 20×20 像素区域算 alpha 均值，取四角最大者；底部中间区域（高度 70% 以下、宽度 30%~70%）算 alpha 均值；两者都 < 10 → 判「真透明」；否则 → 「不是真透明」（没通道 / 白底 / 棋盘格画进图里 都归这档）。~~ 已被取代（修订二）：「下半中间留白区」只适合主体偏上的素材，居中、贴底的真透明图会被误判（见「背景」实测）。新判法如下。
- （修订二）判定逻辑：
  - 像素分档：alpha ≤ 5 = 全透明；alpha ≥ 250 = 不透明；其余 = 半透明（放宽是因为上游透明图的不透明区 alpha 只到 252~254，按「= 255」算会报不透明 0%）。
  - 有没有透明通道：原图 mode 为 RGBA / LA / PA，或带 `transparency` 信息 → 有；否则没有。
  - 边框带：四条边各取宽 `max(4px, 短边 × 2%)` 的一圈，算其中「全透明」像素的占比。
  - 结论三档：
    - **真透明**：有通道，且边框全透明占比 ≥ 25%。
    - **存疑**：有通道，且边框全透明占比在 1% ~ 25% 之间 → 「主体贴边，或背景没抠干净，用 `--bg` 预览确认」。
    - **不是真透明**：没通道，或边框全透明占比 < 1%；附原因 = 「没有透明通道」/「有通道但边框不透明」，再附底色判断 = 「疑似棋盘格画进图里」/「白或浅色底」/「其它底」。
  - 底色判断：只看边框里的不透明像素，RGB 每通道除以 16 量化后取最多的两种颜色：两色都是浅灰（各通道 ≥ 176、通道间差 ≤ 16）、两色不同、第二色占 ≥ 20%、两色合计 ≥ 80% → 疑似棋盘格；否则最多那种是浅色且占 ≥ 80% → 白或浅色底；否则 → 其它底。
  - 原型已用 Pillow 合成 7 类图跑过（居中贴纸、贴底主体、主体占满下部且 alpha=253、白底无通道、白底有通道、棋盘格画进图里、深色场景），结论都对。
- （修订二）实现只用 Pillow（`getchannel` / `crop` / `ImageStat` / `getcolors` 等），**不引入 numpy**。
- 报告输出（stdout）：文件名、尺寸、mode、全透明 / 半透明 / 不透明占比、~~四角 alpha、留白区均值~~（已被取代（修订二）：改为边框全透明占比）、结论（含原因）。
- `--bg RRGGBB`：把图按 alpha 叠到指定底色上，生成 `<原名>_on_<rrggbb>.jpg`（JPEG 质量 90），打印预览路径；不给 `--bg` 不生成预览。
- 依赖：Pillow（仅此工具需要，`draw.py` 不依赖）。未装时给「pip install Pillow」提示，退出码 2。
- 暴露可 import 的 `analyze(path) -> list[str]`（逐行报告文本、末行为结论），`draw.py --inspect` 复用同一函数。
